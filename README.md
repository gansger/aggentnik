# Аггентник

Панель для сервера на Raspberry Pi: перетаскиваешь архив с сайтом в браузере, а сервер сам его распаковывает, ставит зависимости, собирает и запускает. В панели видно состояние сайта, журналы и ссылка на него.

## Установка

Все команды выполняются на самом сервере. Открой на нём терминал и запусти:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/gansger/aggentnik/main/install-docker.sh)"
```

Установщик спросит домен, почту и порт панели, покажет итоговый адрес и попросит подтверждение. После этого он при необходимости поставит Docker, соберёт образ и запустит панель. На экране видны только этапы с индикатором, подробности пишутся в `/var/log/aggentnik-install.log`. В конце установщик покажет адрес и пароль. Пароль показывается один раз.

Та же команда обновляет панель или меняет домен: сайты, пароль и настройки сохраняются. Если на сервере стоит старая версия без Docker, установщик предложит её перенести. После переноса сайты с Python и зависимостями Node.js нужно один раз пересобрать кнопкой «Пересобрать».

Если оставить домен пустым и подтвердить, панель запустится по HTTP без шифрования. Такой вариант подходит только для домашней сети.

### Что нужно для домена и сертификата

Let's Encrypt проверяет домен, подключаясь к серверу из интернета. Поэтому разрешений на самом сервере мало, запрос должен дойти до него снаружи:

1. **A-запись.** У регистратора домена создай A-запись на внешний адрес сервера. Если у домена есть AAAA-запись, она тоже должна вести на сервер, иначе удали её.
2. **Проброс на роутере.** Проброси на локальный адрес сервера порт 80 и порт панели, по умолчанию 7700. Порт 80 нужен и для выдачи сертификата, и для его продления.
3. **Настоящий внешний адрес.** Адрес WAN в настройках роутера должен совпадать с внешним адресом сервера. Если они разные, провайдер использует CGNAT, и входящие соединения не дойдут: нужен белый IP-адрес у провайдера.
4. **VPN.** Если VPN на сервере пускает через себя весь трафик, ответы на входящие соединения уходят в туннель. На время проверки его нужно выключить, либо настроить так, чтобы он не забирал весь трафик.

Если провайдер закрывает только порт 80, можно пробросить внешний порт 443 на порт панели: Caddy умеет получать сертификат и так.

Если сертификат не получен, установщик сам проверит домен, порты и связь с Let's Encrypt и напишет, что исправить. Проверка портов идёт через сервис check-host.net. Запускать установку заново после исправления не нужно: Caddy повторяет попытки сам. Проверить можно так: открой `http://домен` с телефона через мобильный интернет, без Wi-Fi. Если страница не открывается, не дойдёт и Let's Encrypt.

Сертификат получает и продлевает контейнер Caddy.

### Что запускается

| Контейнер | Зачем | Права |
| --- | --- | --- |
| `panel` | Панель и все сайты | Обычный пользователь. Из файлов сервера ему доступна только папка `/var/lib/malinnik` |
| `caddy` | HTTPS и сертификат, только при указанном домене | Обычные |

Данные лежат на самом сервере, в `/var/lib/malinnik`: сайты, пароль и настройки. Сертификаты лежат в томе Docker `aggentnik_caddy-data`.

### Команды

Выполняй их на сервере. Сначала перейди в папку панели:

```bash
cd /opt/aggentnik
```

Состояние контейнеров:

```bash
sudo docker compose ps
```

Журнал панели:

```bash
sudo docker compose logs -f panel
```

Журнал сертификата:

```bash
sudo docker compose logs -f caddy
```

Сменить пароль:

```bash
sudo docker compose exec panel python3 -m malinnik set-password && sudo docker compose restart panel
```

Перезапуск завершает открытые сессии, поэтому после него со старым паролем войти нельзя.

Если панель недоступна по домену, запусти установщик ещё раз и оставь домен пустым: панель откроется по адресу `http://локальный-адрес-сервера:7700`.

### Удаление и чистая установка

Все команды выполняются на сервере. **Удаление необратимо:** вместе с панелью исчезнут все загруженные сайты, их данные, пароль и настройки. Docker остаётся на сервере: повторная установка его не требует.

Если что-то из этого нужно сохранить, сначала сделай копию в домашнюю папку:

```bash
sudo tar -czf ~/aggentnik-backup.tar.gz -C /var/lib malinnik
```

**1. Останови и удали контейнеры.** Перейди в папку панели:

```bash
cd /opt/aggentnik
```

Эта команда удаляет контейнеры, сертификаты и настройки Caddy. Let's Encrypt выдаёт не больше пяти одинаковых сертификатов на домен в неделю, поэтому при частых переустановках убери из неё `--volumes`, чтобы сертификаты сохранились.

```bash
sudo docker compose --profile domain down --volumes --remove-orphans
```

Вернись из папки, которую сейчас удалишь, и удали образ панели и том от старой версии с VPN. Если их нет, сообщения об ошибке можно не учитывать.

```bash
cd ~
```

```bash
sudo docker image rm aggentnik:local
```

```bash
sudo docker volume rm aggentnik_vpn-socket
```

**2. Удали файлы панели, сайты и журнал установки.**

```bash
sudo rm -rf /opt/aggentnik /var/lib/malinnik /var/log/aggentnik-install.log
```

**3. Убери следы старых версий.** Этот шаг нужен, только если раньше стояла версия без Docker или с VPN. Сообщения о том, что службы или файла нет, можно не учитывать.

Отключи старый VPN панели. Свой VPN с другим именем эти команды не затронут:

```bash
sudo awg-quick down /etc/amnezia/amneziawg/malinnik0.conf
```

```bash
sudo rm -rf /etc/amnezia/amneziawg/malinnik0.conf /var/lib/malinnik-vpn
```

Удали старые службы и их файлы:

```bash
sudo systemctl disable --now malinnik malinnik-vpn
```

```bash
sudo rm -rf /opt/malinnik /etc/systemd/system/malinnik.service /etc/systemd/system/malinnik.service.d /etc/systemd/system/malinnik-vpn.service /etc/malinnik-https-domain
```

```bash
sudo systemctl daemon-reload
```

```bash
sudo userdel malinnik
```

Убери настройку nginx от старой версии:

```bash
sudo rm -f /etc/nginx/conf.d/malinnik.conf /etc/nginx/conf.d/malinnik.conf.disabled
```

Выключи nginx и таймер продления certbot, только если они стояли лишь ради панели. Nginx занимает порт 80, который нужен для сертификата. Если на нём работают другие сайты, не выключай его: установщик сообщит, что порт занят.

```bash
sudo systemctl disable --now nginx certbot.timer
```

**4. Проверь, что порт 80 свободен.** Команда не должна вывести ни одной строки с портом:

```bash
sudo ss -ltnp 'sport = :80'
```

**5. Поставь заново.** Установщик снова спросит домен, почту и порт и выдаст новый пароль:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/gansger/aggentnik/main/install-docker.sh)"
```

## Как пользоваться

- **Новый сайт:** перетащи архив на страницу. Название берётся из имени файла.
- **Обновить сайт:** перетащи архив прямо на строку сайта или загрузи архив с тем же именем. Порт не меняется.
- **Архивы:** ZIP, TAR, TAR.GZ, 7Z, RAR. Папку нужно сначала упаковать.

Каждый сайт получает свой порт из диапазона 8100–8199 и открывается по адресу `http://адрес-сервера:порт`.

## Публикация в интернете

Кнопка «Опубликовать» у сайта открывает к нему доступ через Cloudflare Tunnel: появляется ссылка вида `https://случайные-слова.trycloudflare.com` с HTTPS. Порты на роутере открывать не нужно, аккаунт и домен тоже. Туннель ведёт только на порт этого сайта, панель через него недоступна.

Это быстрый туннель, и у него есть ограничения:

- адрес случайный и меняется при перезапуске панели или сервера, а новый приходит в Telegram, если он настроен;
- Cloudflare предназначает такие туннели для проб и не гарантирует их работу;
- посетители видят всё, что отдаёт сайт, поэтому проверь его перед публикацией. Для Django добавь адрес в `ALLOWED_HOSTS`. Панель скрывает `.env` и файлы баз только у статических и PHP-сайтов; приложения на Node и Python сами решают, что отдавать.

## Уведомления и команды в Telegram

Настройка занимает минуту, шаги показаны в карточке: создать бота у @BotFather, вставить токен, написать боту и нажать «Найти мой чат».

Приходят сообщения об упавшем и восстановившемся сайте, результате установки, новом публичном адресе, перегреве, нехватке питания и места на диске и запуске панели. Если связи с Telegram нет, сообщения ждут в очереди до часа; при перезапуске панели очередь теряется.

| Команда | Что делает |
| --- | --- |
| `/status` | Сервер и все сайты одним сообщением |
| `/sites` | Список сайтов с кнопками |
| `/site имя` | Карточка сайта с кнопками управления |
| `/logs имя` | Последние строки журнала |
| `/restart имя`, `/run имя` | Перезапустить, запустить |
| `/stop имя` | Остановить, с подтверждением |
| `/publish имя`, `/unpublish имя` | Открыть в интернете или снять с публикации, с подтверждением |
| `/help` | Справка |

Имя можно не писать: бот предложит выбрать сайт. Хватит и начала имени.

Как бот защищён:

- команды выполняются только из привязанного личного чата и только при включённом переключателе в панели; сообщения из других чатов бот молча игнорирует, в группах команды не работают;
- команды, отправленные более двух минут назад, не выполняются: иначе старый `/stop` сработал бы после включения панели;
- кнопка подтверждения действует пять минут и срабатывает один раз;
- удалять сайты и загружать код через бота нельзя.

Береги токен: с ним нельзя подать команду от твоего имени, но можно читать сообщения, которые приходят боту, и писать от лица бота. В журналах сайта могут быть секреты, и `/logs` отправляет их в Telegram.

У одного бота может быть только одна панель. Если запустить вторую с тем же токеном, панель покажет ошибку.

## Что панель определяет сама

Проверки идут сверху вниз, срабатывает первая подходящая.

| В архиве | Что происходит |
| --- | --- |
| `start.sh` | Запускается `bash start.sh` |
| `index.php`, `public/index.php`, `*.php` | Встроенный сервер PHP |
| `package.json` | `npm install`, `npm run build`, затем `npm start` или раздача `dist`, `build`, `out` |
| `manage.py` | Django: виртуальное окружение, зависимости, `migrate`, `runserver` |
| `app.py`, `main.py` и подобные | Flask через waitress, FastAPI через uvicorn, иначе просто запуск файла |
| `index.html` | Статический сайт, работают и маршруты одностраничных приложений |

Если панель ошиблась или не поняла тип, укажи свою команду в настройках сайта и нажми «Пересобрать». Порт доступен как `$PORT`.

Панель учитывает, что архив собран на Windows:

- убирает `node_modules` и виртуальные окружения: в них файлы под другую систему;
- повторяет установку без `package-lock.json`, если первая попытка не удалась;
- исправляет окончания строк в `.sh`, русские имена файлов из ZIP и кодировку `requirements.txt`;
- убирает из `requirements.txt` пакеты только для Windows, например `pywin32`.

## Что важно знать

**Порт.** Сайт должен читать порт из переменной `PORT`. Если порт задан в коде жёстко, панель его найдёт и покажет верную ссылку, но два таких сайта на одном порту не уживутся.

**Обновления и данные.** При обновлении создаётся новая папка версии, а прошлая остаётся для отката. Из неё переносятся файлы, которых нет в новом архиве: `*.db`, `*.sqlite`, `*.sqlite3`, `.env` и содержимое папок `uploads`, `media`, `data`, `storage`. Если в архиве лежит своя база, она заменит рабочую. Самое надёжное место для данных — папка из переменной `DATA_DIR`: обновления её не трогают.

**Откат.** «Вернуть прошлую версию» возвращает и файлы прошлой версии, включая её копию базы. Изменения, сделанные после обновления, в ней не появятся.

**Сбои.** Если новая версия падает сразу после запуска, панель сама вернёт прошлую. Упавший сайт перезапускается; после пяти быстрых падений подряд попытки прекращаются до ручного запуска.

**Безопасность.**

- С доменом панель доступна из интернета и защищена только HTTPS и паролем, а через неё можно запустить код на сервере. Используй длинный случайный пароль. Без домена панель работает по HTTP, в таком виде не открывай её порт в интернет.
- Панель запускает код из загруженных архивов. Все сайты работают от одного пользователя внутри контейнера и могут читать файлы друг друга и самой панели, включая токен Telegram, поэтому загружай только то, чему доверяешь.
- Сайты работают по HTTP на портах 8100–8199. Если эти порты проброшены на роутере, сайты доступны напрямую и без шифрования. HTTPS для них даёт кнопка «Опубликовать».

## Разработка

```bash
python -m malinnik --data dev-data serve --host 127.0.0.1
```

```bash
python -m unittest discover -s tests
```

Панель написана на Python без внешних зависимостей. Нужен Python 3.9 или новее.

| Файл | За что отвечает |
| --- | --- |
| `install-docker.sh` | Установка и обновление |
| `malinnik/archive.py` | Распаковка архивов |
| `malinnik/detect.py` | Определение типа сайта |
| `malinnik/sites.py` | Установка, запуск и присмотр за процессами |
| `malinnik/metrics.py` | Показатели из `/proc` |
| `malinnik/tunnel.py` | Публикация через Cloudflare |
| `malinnik/telegram.py`, `malinnik/alerts.py` | Связь с Telegram и выбор, о чём сообщать |
| `malinnik/bot.py` | Команды и кнопки бота |
| `malinnik/server.py` | HTTP API |
| `malinnik/web/` | Интерфейс |
